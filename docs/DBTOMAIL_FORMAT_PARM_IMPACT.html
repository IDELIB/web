DBTOMAIL コマンド ファイル形式パラメーター追加 影響調査レポート

対象アプリ: MAI/400 (APP_ID 5) / ソース参照: MAIV300S ライブラリー / Understand 最終スキャン: 2026-10-08 (調査時点で6日前) / 調査日: 2026-10-14

1. 概要

リスク評価: 低〜中

  • Understand 上の依存は浅く、影響は DBTOMAIL 自身と DBTOCSV 系プログラムにほぼ閉じています。
  • 5つの言語版 DBTOMAIL コマンドが PGM MAI/DBTOMAIL を共有しています。メッセージ、ヘルプ、ビルド CL の更新箇所が多くなります。
  • 「ファイル形式」は、添付ファイルの出力形式を選ぶパラメーター(例: FORMAT(*CSV *TSV …))と解釈しました。形式の候補値と、形式で出力内容が変わる範囲は未確認です。

4. 設計上の注意点

  1. PARM の位置: DBTOMAIL.C は argv[n] の位置で引数を取得する(行104〜126)。途中に挿入すると以降の argv が全てずれる。末尾(GSKAPPID の後ろ、argv[21])への追加が最小変更。ただし画面表示順も末尾になる。
  2. 既存呼び出し元: DFT を付ければキーワード指定の既存呼び出しは影響なし。位置指定でも末尾追加なら影響なし。例: QCLSRC/TESTIBMNA3.CLP はキーワード指定。
  3. TOCCSID の不整合: DBTOMAIL.C の tccsid = 932; は固定(行195)。画面の *UTF8 指定は DBTOCSV 側(PTOCCSID)にのみ効く。形式と文字コードの組み合わせを仕様化する場合は見直し候補。
  4. DBTOCSV の引数名: DBTOCSV.CMD は STMFCCSID、CLP 側の変数は &TCCSID。位置渡しのため動作はするが、引数追加時は順序に注意。
  5. 作業中のソース: DBTOMAIL2.CMD(「修正中」、BODY01〜10 などを追加)と DBTOMAIL2.C が存在する。追加先をどちらにするか要確認。これらは Understand の依存検索に出てこなかった。

5. 盲点

  • C 言語からの DBTOCSV 呼び出し(#pragma linkage)はスキャンで検出されない。
  • 外部(ジョブスケジューラー、メニュー、他ライブラリー)の DBTOMAIL 呼び出しは捕捉できない。スキャン対象は7ライブラリーのみ。
  • 動的呼び出し・動的 SQL は検出されない。今回の対象は HAS_DYNAMIC_SQL=N。
  • スキャンは6日前のスナップショット。
  • 一部のソース検索は並列実行時に接続エラーとなった。確認できなかった箇所は #17 に記載。

6. 次のステップ

  1. 形式の仕様(候補値、拡張子、MIME、区切り文字)を決める。
  2. 追加位置(末尾か途中か)と、修正対象が DBTOMAIL か DBTOMAIL2 かを決める。
  3. 仕様確定後、CMD、C、CLP、RPGLE、メッセージ、ヘルプの修正と再ビルドを実施する。
